# 차곡 by 바라티

Google 로그인 후 닉네임을 정하고 보이차·우롱차·홍차를 기록하는 웹사이트입니다.

## 계정별 서버 저장

Firebase Authentication으로 로그인하고 Firestore `users/{uid}` 문서에 닉네임, 비공개 기록, 저장 목록을 저장합니다. 다른 기기에서도 로그인하면 서버의 정보를 다시 읽습니다. 오프라인 작성은 지원하지 않으며, 서버가 저장을 확인하기 전에는 완료로 표시하지 않습니다. 이전 버전의 개인 댓글·공감·체험 설정은 이전 데이터에만 보관하며 공유하지 않습니다.

문서에는 schema, nickname, payload(JSON), revision, updatedAt만 저장합니다. 초기 버전의 계정별 스냅샷 구조로, payload는 UTF-8 700KB까지 허용합니다. 기록이 늘어나면 개별 기록 문서 구조로 확장해야 합니다.

- 로그인 전·닉네임 설정 전 기능 제한
- 최초 서버 문서 생성 시 해당 계정의 기존 브라우저 데이터를 가져옴
- 서버에 데이터가 이미 있으면 오래된 로컬 데이터로 덮어쓰지 않음
- 기존 로컬 원본은 삭제하지 않음. 다른 기기에만 남은 미이전 기록은 자동 병합하지 않음
- 저장 실패 시 기존 데이터와 입력 폼 유지
- revision 기반 트랜잭션으로 다른 기기의 변경을 덮어쓰지 않음
- 로그아웃·계정 전환 후 이전 요청 결과가 새 계정 화면에 적용되지 않음
- 내 계정의 ‘서버 저장 확인’은 캐시가 아닌 서버를 다시 읽어 현재 정보와 비교

닉네임은 Firestore를 기준으로 모든 기기에서 유지합니다. 구글 이름은 자동 공개하지 않으며, 한글·영문·숫자·밑줄 2~16자, 중복 허용입니다.

## 접근 규칙과 실제 배포

1. Firebase 프로젝트 `chagok1-173f9`의 기본 Cloud Firestore 데이터베이스를 생성합니다.
2. 콘솔 Firestore → 규칙에서 `firestore.rules`를 게시합니다. 또는 인증된 Firebase CLI로 `firebase deploy --only firestore:rules --project chagok1-173f9`를 실행합니다.
3. GitHub Pages에 `dist`를 게시합니다. `publish-chagok.ps1`은 웹사이트를 게시하지만 Firebase 규칙은 자동 게시하지 않습니다.
4. 로그인 → 기록 저장 → 로그아웃 → 다른 브라우저에서 같은 계정 로그인 → 기록 확인을 진행합니다.

Firestore 규칙은 개인 문서의 타인 접근·목록 조회·권한 필드 추가·문서 삭제를 차단합니다. 관리자도 다른 회원의 개인 기록을 읽을 수 없습니다.

## 회원 공유와 관리자

- `posts/{id}`: 회원이 게시한 차생활·이야기. 로그인한 회원에게 실시간으로 표시합니다.
- `posts/{id}/comments/{id}`: 회원끼리 공유하는 댓글. 작성자와 관리자만 삭제할 수 있습니다.
- `announcements/{id}`: 관리자 공지. 모든 로그인 회원에게 표시됩니다.
- 저장 목록은 개인 정보로 유지합니다. ‘저장한 기록’에는 저장한 이야기방 글도 표시합니다.

캘린더 기록은 비공개이며 ‘커뮤니티에 공유’에서 내용을 확인한 뒤 별도 게시글로 등록합니다. 이전 ‘전체 공개’ 기록도 자동 공개하지 않습니다. 원본 기록과 게시글은 각각 수정·삭제합니다. 게시 당시 닉네임을 표시하고 글 수정 시 현재 닉네임을 적용합니다.

관리자는 `leegyuhuen@gmail.com`의 인증된 Google 계정입니다. 서버 규칙이 검증된 이메일과 Google 로그인 제공자를 확인하므로 화면이나 브라우저 저장값을 바꿔도 권한을 얻지 못합니다. 관리자는 공지 등록·삭제, 게시글 숨김·복구, 댓글 삭제를 할 수 있습니다. 작성자는 관리자가 숨긴 글을 수정해도 숨김을 풀 수 없습니다.

회원 피드는 hidden=false 조건으로 조회합니다. 수정 번호를 비교해 오래된 기기의 수정을 차단합니다. 게시글 삭제 시 내용을 비우고 숨김·삭제 상태를 유지하여 다시 공개할 수 없게 합니다. 해당 댓글도 읽을 수 없습니다. 로그아웃하면 공유 데이터와 구독을 초기화합니다.

상위 폴더의 `publish-pilot.ps1`은 새 규칙을 복사하고 Firebase 콘솔을 엽니다. 사용자가 규칙을 게시한 후 Enter를 누르면 기존 GitHub 게시 스크립트를 실행합니다. **Firebase 규칙은 GitHub Pages 배포만으로 변경되지 않습니다.**

규칙 근거: [Firebase 인증 토큰](https://firebase.google.com/docs/reference/rules/rules.firestore.Request), [보안 규칙과 조회 조건](https://firebase.google.com/docs/firestore/security/rules-query).

## 검증

Node.js 24, Java 21 환경:

```text
npm ci
npm run test:ui
npm run test:rules
```

`test:rules`는 Firebase 공식 Firestore Emulator와 실제 배포용 규칙·저장 어댑터를 사용합니다. 실제 운영 계정이나 데이터를 사용하지 않습니다. 다른 기기 복원, 계정별 최초 이전, 저장·삭제, 동시 편집, 비로그인·다른 계정 접근 차단, 필드 및 크기 검증을 검사합니다.

`test:ui`는 모의 인증·저장 서비스를 사용해 로그인 로딩, 실패 시 원본 보존, 로그아웃, 계정 전환 중 응답 처리를 검사합니다.

GitHub Actions의 Verify account storage에서도 같은 검사를 실행합니다. 실제 프로젝트의 규칙 게시와 실제 Google 로그인 후 저장 검증은 별도로 확인해야 합니다.

추가 검증은 서로 다른 회원의 실시간 글·댓글 공유, 관리자 전용 공지·숨김·복구, 미인증 관리자 사칭 차단, 닉네임 변경 후 삭제, 삭제 글 재공개 차단을 포함합니다. UI 검사에는 회원 글의 HTML 이스케이프, 저장한 이야기, 관리자 메뉴 제한, 로그아웃 시 공유 데이터 제거를 포함합니다.

브라우저를 별도의 `demo-chagok` Emulator에 연결해 320~1440px 화면과 두 계정의 글·댓글 공유, 관리자 숨김·복구·공지를 직접 확인했습니다. 테스트 인증 코드와 예시 데이터는 dist에 포함하지 않습니다. 실제 Google OAuth와 운영 규칙 적용 여부는 배포 후 확인해야 합니다.

시행운전 규모의 전체 피드 구독 방식입니다. 글이 많아지면 페이지별 조회를 추가해야 합니다.

## 사진·이벤트 업데이트

- 관리자 메뉴는 검증된 Firebase ID 토큰의 이메일·이메일 인증·Google 제공자가 일치한 계정에만 생성합니다. 일반 회원용 HTML에는 관리자 버튼이 없습니다.
- 차 종류 탭과 선택 항목은 우롱차, 보이차, 홍차 순서입니다.
- 게시글 사진은 3장까지, 입력 파일당 15MB 이하의 JPEG/PNG/WebP를 받습니다. 브라우저에서 최대 1280px JPEG로 변환하고 사진당 data URL 200,000자 이내로 압축합니다. 재인코딩하므로 원본 EXIF 메타데이터는 저장하지 않습니다.
- 사진은 `posts/{id}/media/photos`에 저장하고 화면에 들어온 카드의 사진만 구독합니다. 별도 Firebase Storage 설정은 사용하지 않습니다. 3장 합계 약 600KB 이하로 [Firestore 문서 제한](https://firebase.google.com/docs/firestore/quotas) 안에 보관합니다. 향후 대규모 이미지 서비스로 확대하면 객체 저장소로 이전해야 합니다.
- 글과 사진은 함께 저장·수정·삭제합니다. 사진을 제거하면 미디어 문서도 삭제하며, 숨김·삭제 글의 사진은 다른 회원이 조회할 수 없습니다.
- `events/{id}`는 관리자만 생성·수정·삭제합니다. 작성 중인 초안은 관리자만 보고, 공개·취소된 이벤트는 로그인 회원에게 표시합니다. 시작·종료·장소·안내·공개 상태를 설정하고 시간은 한국 시간으로 표시합니다.
- 사진·이벤트 규칙과 구버전 개인 기록·텍스트 게시글의 호환성을 Emulator에서 검사합니다.

콘솔의 규칙 저장 오류가 계속된다면 상위 폴더의 `publish-update.ps1`을 사용합니다. 로컬에 준비한 공식 Firebase CLI로 로그인하고 `chagok1-173f9`에 규칙을 직접 배포한 뒤 GitHub Pages 게시를 실행합니다. Firebase 규칙 게시에 실패하면 웹사이트 배포를 진행하지 않습니다.
